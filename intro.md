# Project Results Summary

This document provides an overview of the visualization results generated by the `visualize.py` script after an Ensemble Kalman Inversion (EKI) run. The primary goal of this project is to calibrate the runoff coefficient (`Cr`) for a distributed hydrological model. The key innovation is that the `Cr` parameter is not treated as a single global value, but is estimated for distinct geographic sub-watersheds, referred to as "divisions".

The results are located in the `Inverse_Problem/out/visualization/` directory and are designed to offer a comprehensive analysis of the calibration process, from parameter convergence to spatial distribution and event-based performance.

## Visualization Categories

### 1. Parameter Evolution (`parameter/`)

These plots show how the estimated `Cr` value for each individual sub-watershed division evolves over the EKI iterations. They are essential for diagnosing the health and success of the calibration.

*   **Purpose**: To assess convergence and accuracy of the parameter estimation for each division.
*   **What to look for**:
    *   In the `mean_std/` plots, the mean value (solid line) should converge to a stable value.
    *   The uncertainty (shaded area, representing ±1 standard deviation) should decrease over iterations, indicating that the EKI is successfully constraining the parameter.
    *   In simulated-data experiments, the mean should converge towards the red dashed line, which represents the "true" `Cr` value (`Cr_ref`).

### 2. Hydrograph Animation (`hydrograph/`)

These animations provide a direct visual comparison between the model's simulated streamflow and the observed data at specific gauge locations.

*   **Purpose**: To evaluate how well the calibrated model reproduces the observed river discharge over the entire time series.
*   **What to look for**:
    *   The median of the model ensemble (blue line) should track the observed data (black dashed line) as closely as possible.
    *   The uncertainty band (blue shaded area) should be as narrow as possible while still containing the observations.
    *   The visualization also includes rainfall data, plotted on a secondary, inverted y-axis, to show the model's response to precipitation events.
    *   **Ill-Posedness Check**: A key analysis is to check if a good fit in the hydrograph corresponds to an accurate parameter estimation (seen in the parameter plots). If the hydrograph fits well but the parameters are incorrect, it suggests the problem is ill-posed (i.e., multiple different parameter sets can produce the same output).

### 3. Event Statistics (`event_statistics/`)

This provides a more focused analysis on specific high-flow events (e.g., storms). The EKI process is configured to match key characteristics of these events. For each station, a single consolidated plot is generated.

*   **Purpose**: To assess the model's ability to reproduce the magnitude, timing, and shape of individual storm events, which are often of primary interest in hydrology.
*   **What to look for**:
    *   The figure for each station contains five subplots, one for each key event metric (Peak, Mean, Std Dev, Timing Mean, Timing Std Dev).
    *   Within each subplot, the colored lines (representing the simulated mean for each event) should converge towards the corresponding dashed lines (the "true" metric from observed data).

### 4. Spatial Maps (`maps/`)

This directory contains three distinct maps that provide critical spatial context for the model inputs, outputs, and performance.

*   **`final_cr_map_post.png` (Parameter Distribution Map)**: This map visualizes the final calibrated `Cr` parameter values from the last EKI iteration.
    *   **Purpose**: To understand the spatial patterns of the calibrated parameters and identify potential spatial biases in the estimation.
    *   **Interpretation**: The map has two modes depending on the experiment type:
        *   **Real-Data Mode**: Shows the absolute value of the final `Cr` mean for each division, annotated with the mean and standard deviation. This reveals which parts of the watershed require higher or lower runoff coefficients.
        *   **Simulated-Data Mode**: Shows the **percentage error** (`|Cr_calibrated - Cr_true| / Cr_true`) of the estimate, using a binned color scale to highlight areas of high and low accuracy. Each division is annotated with the true value, the calibrated mean, the percentage error, and the standard deviation, providing a comprehensive diagnostic of estimation performance.

*   **`hydrograph_metric_map_post.png` (Hydrograph Performance Map)**: This map displays the locations of all monitored USGS gauges on the river network and provides a detailed, quantitative assessment of the final model's performance at each site.
    *   **Purpose**: To spatially evaluate the model's accuracy and uncertainty across the entire watershed, not just at the assimilation point.
    *   **Interpretation**:
        *   Gauges are marked differently based on their role: **Assimilation Gauge** (cyan), **Downstream Outlet** (yellow star), and **Verification Gauges** (red).
        *   Each gauge is annotated with a detailed box of performance metrics calculated from the final hydrograph, including:
            *   Average relative error over the entire time series.
            *   Maximum ensemble standard deviation (a measure of final uncertainty).
            *   Average relative error for five key event-based metrics (Peak, Mean, Std Dev, etc.), offering a granular look at event performance.

*   **`total_rainfall_map.png` (Rainfall Distribution Map)**: This map, located in its own `rainfall_map` sub-directory, visualizes the primary input driving the model: the rainfall.
    *   **Purpose**: To provide spatial context for the hydrological forcing and to help interpret the resulting `Cr` parameter map.
    *   **Interpretation**:
        *   The map shows the **average rainfall rate (mm/hr)** for each sub-watershed division over the entire simulation period, calculated by aggregating data from numerous individual rainfall files.
        *   Each division is colored according to its average rainfall rate (using a 'Blues' colormap) and annotated with the rate value.
        *   This allows for visual correlation analysis: for example, do areas with higher rainfall rates consistently result in higher or lower calibrated `Cr` values?
