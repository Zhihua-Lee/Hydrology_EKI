# Output Directory Structure (`out/`)

This directory stores the **final, user-facing results** of the Data Assimilation (DA) run. The files here are intended for analysis, visualization, and interpretation of the model's performance and the parameter estimation process.

This contrasts with the `tmp/` directory, which holds temporary, intermediate files required during the computation (e.g., HPC job scripts, serialized data for workers, raw model outputs per member) and is generally safe to be cleaned between runs.

The `out/` directory is typically organized into the following subdirectories:

-   [`csv/`](#csv---human-readable-time-series-results)
-   [`npy/`](#npy---full-ensemble-data-for-analysis)
-   [`visualization/`](#visualization---plots-and-animations)

---

## `csv/` - Human-Readable Time Series Results

This directory contains the core results of the DA run in a human-readable CSV format. These files are ideal for quick inspection, plotting with standard tools (like Excel or Pandas), and sharing. The results are typically saved as the **mean of the ensemble** at each time step, representing the "best guess" of the system's state and parameters.

### Physical State: `analysis_q_mean_t{t:03d}.csv`

This file represents a snapshot of the mean physical state (discharge) of the entire river network at a specific time step. A new file is created for each time step of the assimilation window.

-   **Naming Convention**: `t` is followed by a zero-padded integer representing the time step index. For example, `analysis_q_mean_t012.csv` contains the results for the 12th time step.
-   **Content**:
    -   `link_id`: The unique identifier for each river segment in the model.
    -   `discharge_m3s`: The ensemble-mean discharge (streamflow) in cubic meters per second ($m^3/s$) for that link after the analysis (update) step.

### Parameter Estimation Outputs (`alpha_r`)

The following files provide a comprehensive view of the rainfall correction parameter (`alpha_r`) estimation process, from the initial prediction to the final, smoothed result.

#### 1. Forecast (Prior): `forecast_alpha_mean_timeseries.csv`

-   **Purpose**: Tracks the model's *a priori* prediction for `alpha_r` at each time step `t`, **before** the new observation `y_t` is assimilated.
-   **Content**: `time_step`, `forecast_alpha_mean`.
-   **Use Case**: Comparing this file with the `realTimeOptimal` file reveals the magnitude of the correction (the "innovation") applied at each step.

#### 2. Real-Time Analysis (Posterior): `analysis_alpha_mean_timeseries_realTimeOptimal.csv`

-   **Purpose**: Tracks the **best real-time estimate** of `alpha_r` for the *current* time step `t`, **after** assimilating the observation `y_t`.
-   **Content**: `time_step`, `analysis_alpha_mean`.
-   **Use Case**: This is the primary output for evaluating the system's real-time performance. It shows the final decision on the rainfall bias at each moment.

#### 3. Smoothed Window Snapshot: `analysis_alpha_window_t{t:03d}.csv`

-   **Purpose**: Provides a complete "snapshot" of the entire smoothed parameter history window `[alpha_t, alpha_t-1, ...]` as it exists in memory at the end of each time step `t`.
-   **Structure**: A new, separate file is created for each time step.
-   **Content**: `history_lag`, `smoothed_alpha_mean`.
-   **Use Case**: Comparing `..._t010.csv` with `..._t011.csv` directly shows how the estimate for `alpha_10` was improved by the arrival of the observation `y_11`.

#### 4. Retrospective Smoothing Matrix: `analysis_alpha_mean_timeseries_retrospectiveOptimal.csv`

-   **Purpose**: This file provides the most detailed view of the smoothing process. It tracks how the estimate for a single historical `alpha` (e.g., `alpha_10`) is continuously refined over time as more and more future observations become available.
-   **Structure**: A single file that grows into a matrix. Each row represents a historical time step. Each column `corrected_at_t{T}` shows the state of the estimates at the end of time step `T`.
-   **Content**: The value at `(row=t, column=T)` is the mean estimate of `alpha_t` after assimilating all data up to time `T`.
-   **Use Case**: Plotting a single row shows the convergence of a historical parameter's estimate. The diagonal of this matrix is identical to the `realTimeOptimal` time series.

## `npy/` - Full Ensemble Data for Analysis

This directory stores the complete dataset for the entire ensemble in NumPy's binary `.npy` format. These files are not human-readable but are highly efficient for loading into Python scripts for detailed analysis, such as calculating uncertainty bounds, plotting distributions, or performing further statistical tests. These files are typically generated by post-processing or visualization scripts (like `visualize.py`).

### `{iteration}_post_params_particles.npy`

-   **Naming Convention**: `{iteration}` is the EKI iteration number (in a sequential DA context, this might be saved at specific intervals or at the end). `_post_` indicates the data is from *after* the Kalman update.
-   **Content**: A 3D NumPy array containing the full ensemble of the estimated **physical parameters** (e.g., `$Cr$`).
-   **Shape**: `(n_active_params, n_divisions, n_ensembles)`.

### `{iteration}_post_particles.npy`

-   **Naming Convention**: Similar to the above, but for model outputs.
-   **Content**: A 3D NumPy array containing the full ensemble of the **simulated model outputs** (hydrographs) generated using the posterior parameters.
-   **Shape**: `(n_ensembles, n_timesteps, n_links)`.

## `visualization/` - Plots and Animations

This directory contains all graphical outputs generated by the `visualize.py` script. It provides a quick, visual summary of the DA run's performance.

### `hydrograph/`

-   **`animation/`**: Contains animated GIFs (`.gif`) for each monitored gauge, showing the evolution of the simulated hydrograph ensemble (median and 95% confidence interval) against the observations as the DA progresses through iterations/time.
-   **`frames/`**: Contains the individual image files (`.png`) that were used to create the animations.

### `parameter/`

-   **`ensemble/`**: "Spaghetti plots" showing the trajectories of every single ensemble member for each estimated parameter over the iterations.
-   **`mean_std/`**: Plots showing the evolution of the ensemble mean for each parameter, with the uncertainty represented by a shaded area (mean ± one standard deviation).
-   **`consolidated/`**: A grid of plots showing the mean evolution for a single parameter across all watershed divisions in one figure, for easy comparison.

### `maps/`

-   Contains geospatial plots (`.png`) that visualize the spatial distribution of key results.
    -   `final_cr_map_...`: A map showing the final, spatially distributed values of the calibrated `$Cr$` parameter across the watershed divisions.
    -   `hydrograph_metric_map_...`: A map of the river network highlighting the locations of stream gauges and annotating them with key performance metrics (e.g., relative error in peak flow, timing, etc.).
    -   `total_rainfall_map.png`: A map showing the average rainfall rate aggregated over each watershed division for the simulation period.

### `event_statistics/`

-   Contains plots that analyze the performance of the model for specific rainfall-runoff "events" (e.g., individual storms). These plots track the evolution of event-based metrics (like peak flow, total volume, recession rate) as the DA system iterates, comparing the simulated metrics to the observed ones.
